rxunicode Reference Documentation

The RexxUnicodeServices class is a native class that exposes the Unicode services supported by ooRexx. Its current implementation is based on the utf8proc library embedded in ooRexx.

rxunicode.cls is a package that defines:

  • The RexxUnicode class, a subclass of RexxUnicodeServices.
  • The RexxUnicodeCodepointSupplier class.
  • The RexxUnicodeGraphemeSupplier class.
  • The RexxUnicodeReverseCodepointSupplier class.
  • The RexxUnicodeReverseGraphemeSupplier class.
  • The RexxUnicodeStringIndexer class.
  • The RexxUnicodeCharacter class.
  • The ICU4ooRexxInterface class.

[!CAUTION]
Testing these classes from ooRexxShell with TUTOR enabled showed that a defensive barrier is needed. This problem is not limited to TUTOR classes; it can occur with any String subclass that overrides ~length or ~substr.

In case of errors like

  • Argument <name> class: expected String, found Text.
  • Argument <name> class: expected String, found Bytes.

use tutor off for a permanent workaround,
or use ~string for a temporary workaround.

The requestBaseString routine ensures that any string passed as an argument is a .String instance, not an instance of a subclass of .String.

No attempt is made to obtain a string from these arguments.

This check is intended to detect accidental mixing of Unicode-aware objects with byte strings and to allow users to adapt their code accordingly (typically by requesting a .String from their Unicode objects).

See the examples at the end of rxunicode.cls showing the internal errors that can occur when mixing graphemes and bytes.

Note on terminology: This documentation and the code comments use the term "codepoint" instead of "code point", except when quoting definitions from the Unicode Standard.

Note on examples: The special syntax expression= or expression== is a feature of ooRexxShell. It is a shortcut for displaying the result of expression. Collections are displayed either in compact form (when the expression ends with =) or in expanded form (when it ends with ==). If you are using rexxtry or running a script, use say expression instead.

1.   RexxUnicodeServices Class

The RexxUnicodeServices class cannot be instantiated.
Its services are provided through class methods.

This native class is always available; there is no need to load rxunicode.cls.

In the examples, you can replace RexxUnicodeServices by RexxUnicode if you loaded rxunicode.cls.

1.1.1.   C2U

.RexxUnicodeServices~C2U( string, buffer = .nil )

Returns an ASCII string containing a sequence of U+XXXX (4 to 6 hex digits).

If a buffer is passed as an argument, the resulting string is appended to the buffer, and the buffer is returned.

Examples:

.RexxUnicodeServices~C2U("Noël 🎅")=                        -- 'U+004E U+006F U+00EB U+006C U+0020 U+1F385'
.RexxUnicodeServices~C2U("Noël 🎅", .MutableBuffer~new)=    -- M'U+004E U+006F U+00EB U+006C U+0020 U+1F385'

-- Invalid string
-- U+FFFD Substitution of Maximal Subparts
-- https://www.unicode.org/versions/Unicode17.0.0/core-spec/chapter-3/#G68064
.RexxUnicodeServices~C2U("F4 91 92 93 FF 41 80 BF 42"x)=    -- 'U+FFFD U+FFFD U+FFFD U+FFFD U+FFFD U+0041 U+FFFD U+FFFD U+0042'
.RexxUnicodeServices~C2X("F4 91 92 93 FF 41 80 BF 42"x)=    -- 'F4 91 92 93 FF 41 80 BF 42'
-- https://www.unicode.org/versions/Unicode17.0.0/core-spec/chapter-3/#G68202
.RexxUnicodeServices~C2U("E1 80 E2 F0 91 92 F1 BF 41"x)=    -- 'U+FFFD U+FFFD U+FFFD U+FFFD U+0041'
.RexxUnicodeServices~C2X("E1 80 E2 F0 91 92 F1 BF 41"x)=    -- 'E180 E2 F09192 F1BF 41'

1.1.2.   C2X

.RexxUnicodeServices~C2X( string, buffer = .nil )

Returns a string representing the encoded codepoints of string in hexadecimal.
The codepoints are separated by a single space.

If a buffer is passed as an argument, the resulting string is appended to the buffer, and the buffer is returned.

Examples:

.RexxUnicodeServices~C2X("Noël 🎅")=                        -- '4E 6F C3AB 6C 20 F09F8E85'
.RexxUnicodeServices~C2X("Noël 🎅", .MutableBuffer~new)=    -- M'4E 6F C3AB 6C 20 F09F8E85'

1.1.3.   codepointAsciiPrintableString

.RexxUnicodeServices~codepointAsciiPrintableString( codepoint, buffer = .nil )

Returns an ASCII printable string representation for the given codepoint.

ASCII printable codepoints are returned as their ASCII representation;
all other codepoints are returned as a Unicode escape notation.

If a buffer is passed as an argument, the resulting string is appended to the buffer, and the buffer is returned.

See also .RexxUnicodeServices~codepointUtf8PrintableString.

Examples:

.RexxUnicodeServices~codepointAsciiPrintableString(0)=          -- '\u0000'
.RexxUnicodeServices~codepointAsciiPrintableString(65)=         -- 'A'
.RexxUnicodeServices~codepointAsciiPrintableString(224)=        -- '\u00E0'
.RexxUnicodeServices~codepointAsciiPrintableString("D800"~x2d)= -- '\uD800'

-- Since the special value -1 is not printable, it is represented using Unicode escape notation.
.RexxUnicodeServices~codepointAsciiPrintableString(-1)=         -- '\UFFFFFFFF'

1.1.16.   codepointIsPrintable

.RexxUnicodeServices~codepointIsPrintable( codepoint )

Returns .true if the codepoint is printable.

Rules (where display width is the value returned by codepointCharWidth):

  • Codepoints having a display width of 0 are considered non-printable.
  • Mc, Me and Mn codepoints are considered printable, even though they have a display width of 0, because some fonts provide visible glyphs for them.
  • Unassigned (Cn) and private-use (Co) codepoints are considered non-printable, even though they have a display width of 1.
  • Other codepoints are considered printable.

Examples:

.RexxUnicodeServices~codepointIsPrintable(0)=             -- 0
.RexxUnicodeServices~codepointIsPrintable(65)=            -- 1
.RexxUnicodeServices~codepointIsPrintable("D800"~x2d)=    -- 0

-- The special value -1 is not printable
.RexxUnicodeServices~codepointIsPrintable(-1)=            -- 0

1.1.27.   graphemeBreakBackward

.RexxUnicodeServices~graphemeBreakBackward( string, indexB, codepoint1, codepoint2 )

.RexxUnicodeServices~graphemeBreakBackward(
    string,     -- (in)     A UTF-8 string.
    indexB,     -- (in)     The byte index (1-based) of codepoint1.
    codepoint1, -- (in)     The first codepoint.
    codepoint2  -- (in)     The second codepoint, immediatly following codepoint1 in forward order.
    )

Given a pair of consecutive codepoints, return .true if a grapheme break is permitted between them when processing the pair backward.

https://www.unicode.org/reports/tr29/#Grapheme_Cluster_Boundaries

Iterates backward from a KNOWN boundary (default: one past the end of the string, i.e. the whole string's right edge). This is deliberately not a random-access primitive -- per UAX #29 6.4, starting from an arbitrary, unverified offset would require a separate "safe point" search. Starting from a genuine boundary avoids that; what remains is the residual cost described below.

Rules GB3, GB6-GB9b are simple, direction-symmetric pairwise lookups: no lookback needed, forward or backward.

Three rules are not:

  • GB9c (Indic conjunct clusters)
  • GB11 (emoji ZWJ sequences)
  • GB12/13 (regional indicator / flag sequences)

These are left-anchored: correctly resolving them going backward requires rescanning the run of Extend/Linker/RI scalars each time one is encountered, since (unlike forward iteration) there's no running "parity" or "seen a linker" state carried over from a previous step to reuse.

Swift's stdlib has the exact same property and documents it as accepted, non-quadratic-in-practice behavior (see StringGraphemeBreaking.swift, _previousGraphemeClusterBoundary).

Example - GB12/13 lookback

GB12/13 (regional indicator / flag sequences) is quadratic.

GB12/13 lookback triggers on every internal pair of a homogeneous RI run, because its trigger condition is "both sides are the same class" (prop1==RI && prop2==RI). In a run of N consecutive RI codepoints, essentially every adjacent pair re-fires the check, and each firing rescans the whole preceding RI stretch from scratch. That's O(N) calls × O(N) average scan = O(N²).

Repeat the Regional Indicator Symbol Letter, e.g. 🇦 = U+1F1E6:

🇦🇦🇦🇦🇦...🇦 (N copies of U+1F1E6)

This isn't a sequence of valid flag pairs semantically — it doesn't matter, GB12/13 only cares about the boundclass RI, not validity as a country code.

Example - GB9c/GB11 lookback

GB9c and GB11 are not quadratic.

GB9c and GB11 trigger on an asymmetric transition — "arriving at a Consonant" / "arriving at a Pictograph" — not on two sides matching. Hitting any Consonant (or Pictograph) during the backward scan halts it unconditionally, regardless of whether the rule's specific condition (a Linker in between, etc.) is satisfied.

That means: for consonants c₁ < c₂ < ... < cₖ in the string, the scan triggered by cᵢ can never run past cᵢ₋₁ — it stops there. Since each pair is tested exactly once during a full traversal, these per-consonant scan intervals are disjoint and telescope to O(n) total, no matter how the consonants are spaced.

Same argument for pictographs and GB11.

So a single call can still be O(run length) — worth demonstrating for perf-testing one grapheme decode's worst case — but it can't accumulate to O(n²) over a full string traversal the way RI does.

1.1.39.3.   'nlf' argument

https://www.unicode.org/versions/Unicode17.0.0/core-spec/chapter-5/#G10213

-- Value to pass as the 'nlf' argument to utf8Transform (default: 0 no transformation).
-- These constants are declared in the RexxUnicode class.
-- If rxunicode.cls is not loaded, use the numeric value directly..
::constant NLF2LF 1
::constant NLF2LS 2
::constant NLF2PS 3

NLF2LF
converts LF, CRLF, CR and NEL into LF.

NLF2LS
Converts LF, CRLF, CR and NEL into LS.
NLF sequences (LF, CRLF, CR, NEL) represent a line break and are converted to the Unicode Line Separator (LS) codepoint.

NLF2PS
Converts LF, CRLF, CR and NEL into PS.
NLF sequences (LF, CRLF, CR, NEL) represent a paragraph break and are converted to the Unicode Paragraph Separator (PS) codepoint.

-- Value to pass as the `normalization` argument to utf8Transform (default: 0 no normalization).
-- These constants are declared in the RexxUnicode class.
-- If rxunicode.cls is not loaded, use the numeric value directly.

If normalization is not 0, apply the requested normalization.

1.1.39.5.   'stripCC' argument

Strips and/or converts control characters.

NLF-sequences are transformed into space, except if one of the NLF2LS/PS/LF options is given. HorizontalTab (HT) and FormFeed (FF) are treated as a NLF-sequence in this case.

All other control characters are simply removed.

1.1.39.6.   'stripIgnorable' argument

Strips the characters whose property Default_Ignorable_Code_Point is true, such as SOFT-HYPHEN or ZERO-WIDTH-SPACE.

1.1.39.7.   'stripMark' argument

Strips all character markings.

This includes non-spacing, spacing and enclosing (i.e. accents) categories:

  • Mc Spacing Mark
  • Me Enclosing Mark
  • Mn Nonspacing Mark

This option works only with a normalization applied.

1.1.39.8.   'stripNA' argument

Strips the characters whose category is Cn Unassigned.

.RexxUnicode~character( identifier )

.RexxUnicode~stringToNFKC_CF( string, lump= .false, nlf = 0, stripCC = .false, stripMark = .false, stripNA = .false )

Returns the input string normalized to NFKC_CF, with optional transformations applied.

NFKC preserves the original case of letters (e.g., 'A' remains 'A').
In contrast, NFKC_CF applies Unicode case-folding rules to map all characters to a case-insensitive form.

  • Example: The German sharp s ('ß') remains 'ß' in NFKC but maps to 'ss' in NFKC_CF.
  • Example: The Greek final sigma ('ς') maps to the standard sigma ('σ') in NFKC_CF, whereas NFKC leaves it unchanged.

NFKC_CF is specifically optimized for identifier matching.
As part of the "Default Case Folding" algorithm, it removes ignorable characters (such as certain formatting marks or zero-width spaces).
NFKC retains these characters.

See the utf8Transform method for a description of the optional transformation parameters.

3.   RexxUnicodeCodepointSupplier Class

A RexxUnicodeCodepointSupplier instance is an iterator created from a UTF-8 string that allows enumeration of the string's codepoints without an indexer.

Byte indexes are counted from the beginning of the string.
They can be used with String methods and string builtin functions.

Codepoint indexes are counted from the beginning of the string.

  • They can be used with aRexxUnicodeCodepointSupplier~codepointAtIndexC, provided that the supplier can only be advanced sequentially with next.
  • They can be used with aRexxUnicodeStringIndexer~codepointAtIndexC.

See RexxUnicodeReverseCodepointSupplier for a supplier that enumerates codepoints in reverse order.

::requires "rxunicode.cls"

Examples:

-- Example 1
-- the default index type is the codepoint index
-- the default item type is the codepoint as a whole number
.RexxUnicodeCodepointSupplier~new("noël👨‍👩‍👧🎅")==
    /*
    a RexxUnicodeCodepointSupplier 
     1  :  110
     2  :  111
     3  :  235
     4  :  108
     5  :  128104
     6  :  8205
     7  :  128105
     8  :  8205
     9  :  128103
     10 :  127877

-- It's possible to get other types of index and item

7.   RexxUnicodeStringIndexer Class

A RexxUnicodeStringIndexer instance provides direct access to codepoints and graphemes in a UTF-8 string.

When a RexxUnicodeStringIndexer instance is created, a full scan of the UTF-8 string is performed, updating the index and error storage according to the storage settings passed to the new method.

If the indexer is incremental, these methods may complete the storage on demand:

  • codepointAtIndexC
  • codepointIndexB
  • codepointIndexC
  • graphemeAtIndexG
  • graphemeIndexB
  • graphemeIndexG

By default, a RexxUnicodeStringIndexer instance is non-incremental.

For an explanation of storage, see RexxUnicodeStringIndexer~new and RexxUnicodeStringIndexer~newIncremental.

::requires "rxunicode.cls"

  • endCodepointStorageLimit determines how many codepoint indexes can be stored in the end storage.
  • endErrorStorageLimit determines how many error messages can be stored in the end storage.

The start and end storage limits allow fine-tuning of memory usage.

End storage is useful when start storage is limited; it allows sparse storage, where only the starting and ending indexes are stored. Prefer start storage when possible, because it can be more efficient.

Each limit is a strict value that must not be exceeded.
The limits are independent, so gaps between storages are possible.

During initialization

  • A full forward scan of the UTF-8 string is performed to calculate the number of graphemes, codepoints and errors.

    • A grapheme supplier is always used, even if startGraphemeStorageLimit == 0, because the graphemes must be counted.
    • The start storages are updated up to their specified limit.

  • A limited backward scan is performed if any end limit is non-zero.

    • A reverse grapheme supplier is used when the end grapheme storage is enabled; otherwise a reverse codepoint supplier is used.
    • The specified end limits may be decreased to avoid any overlap between the start and end storages.
    • The grapheme and codepoint end storages are updated up to their specified limit.
    • An error is stored when a codepoint or grapheme index referencing an invalid byte sequence is appended, provided that the error end limit has not been reached.
    • The backward scan is stopped when both the codepoint and grapheme end limits are reached. The error end limit does not trigger further decoding.

After initialization

  • The errors "Code point index is not stored" and "Grapheme index is not stored" are raised when a requested index is not stored.

Note

To decode a grapheme, codepoints must be decoded until a grapheme break is detected.

  • When decoding forward, if the end of the string has not been reached, a codepoint beyond the grapheme's last codepoint will be decoded and stored, along with any related error.
  • When decoding backward, if the start of the string has not been reached, the codepoint immediately preceding the grapheme's first codepoint will be decoded and stored, along with any related error.

This extra codepoint (and possibly extra error) is expected and safely handled without duplication.

Invariants

  • At the end of initialization:

    • A full forward scan has been performed, independently of the specified limits:

      • i0sg startGraphemeIndexes~items = min(startGraphemeStorageLimit, graphemeCount).
      • i0sc startCodepointIndexes~items = min(startCodepointStorageLimit, codepointCount).

    • A limited backward scan has been performed, depending on the adjusted limits:

      • i0eg endGraphemeIndexes~items = min(endGraphemeStorageLimit, graphemeCount).
      • i0ec endCodepointIndexes~items = min(endCodepointStorageLimit, codepointCount).

    • i1 The limits are strict, so the start codepoint storage can end in the middle of a grapheme.
      This contrasts with an incremental indexer, where the start codepoint storage ends on a grapheme boundary.

    • i2 The limits are strict, so the end codepoint storage can end in the middle of a grapheme.
      This contrasts with an incremental indexer, where the end codepoint storage ends on a grapheme boundary when the end grapheme storage is enabled.

    • i3 startErrorMessages~items == min(startErrorStorageLimit, errorCount),
      even if no grapheme or codepoint index is stored.

    • i4 endErrorMessages~items == min(endErrorStorageLimit, max(negEndGrapheme, negEndCodepoint)),

      • where endErrorStorageLimit is the value returned by ~limits,
      • where negEndGrapheme and negEndCodepoint are the counts of negative indexes in endGraphemeIndexes and endCodepointIndexes.
      • Exception: when the start and end error storages together hold all errors (startErrorStorageCount + endErrorStorageCount == errorCount), the end storage can hold fewer messages than that value min(...). Some end indexes are then negative without their message, because the message is already in the start storage.

  • At any time after initialization:

    • The storages are never updated:

      • i0sg startGraphemeIndexes~items = min(startGraphemeStorageLimit, graphemeCount).
      • i0sc startCodepointIndexes~items = min(startCodepointStorageLimit, codepointCount).
      • i3 startErrorMessages~items == min(startErrorStorageLimit, errorCount).
      • i0eg endGraphemeIndexes~items = min(endGraphemeStorageLimit, graphemeCount).
      • i0ec endCodepointIndexes~items = min(endCodepointStorageLimit, codepointCount).
      • i4 endErrorMessages~items == min(endErrorStorageLimit, max(negEndGrapheme, negEndCodepoint)) except when startErrorStorageCount + endErrorStorageCount == errorCount.

7.2.2.   newIncremental

RexxUnicodeStringIndexer~newIncremental(
    string,

    -- Start storage adjustable limits
    startGraphemeStorageAdjustableLimit = 1,
    startCodepointStorageAdjustableLimit = 1,
    startErrorStorage = .true,
    
    -- End storage adjustable limits
    endGraphemeStorageAdjustableLimit = 0,
    endCodepointStorageAdjustableLimit = 0,
    endErrorStorage = .false
    )

Creates an incremental indexer for the UTF-8 string string.

Start storage adjustable limits can be specified when creating the indexer; by default, the limit is 1:

  • startGraphemeStorageAdjustableLimit determines the initial number of grapheme indexes that can be stored in the start storage. This limit can be increased during initialization.
  • startCodepointStorageAdjustableLimit determines the initial number of codepoint indexes that can be stored in the start storage. This limit can be increased during initialization.
  • startErrorStorage determines wether error messages are stored in the start storage.

End storage adjustable limits can be specified when creating the indexer; by default, no end storage is allocated (0).

  • endGraphemeStorageAdjustableLimit determines the initial number of grapheme indexes that can be stored in the end storage. This limit can be increased during initialization.
  • endCodepointStorageAdjustableLimit determines the initial number of codepoint indexes that can be stored in the end storage. This limit can be increased during initialization.
  • endErrorStorage determines wether error messages are stored in the end storage.

The start and end storage limits allow fine-tuning of memory usage.

End storage is useful when start storage is limited; it allows sparse storage, where only the starting and ending indexes are stored. Prefer start storage when possible, because it can be more efficient.

The limits are adjusted together to avoid gaps between storages.

During initialization

  • A full forward scan of the UTF-8 string is performed to calculate the number of graphemes, codepoints and errors.

    • A grapheme supplier is always used, even if startGraphemeStorageAdjustableLimit == 0, because the graphemes must be counted.
    • The start limits are adjustable: They may be increased during the scan to ensure that no gap is created between the stored grapheme and codepoint indexes.
    • If the start error storage is enabled, an error is stored when a grapheme or codepoint index referencing an invalid byte sequence is appended.

  • A limited backward scan is performed if any end limit is non-zero.

    • A reverse grapheme supplier is used when the end grapheme storage is enabled; otherwise a reverse codepoint supplier is used.
    • The specified end limits may be decreased to avoid any overlap between start and end storages.
    • The end limits are adjustable, following the same principles as for the forward scan: the grapheme and codepoint limits may be increased as needed, and errors stored if the end error storage is enabled.
    • The backward scan is stopped when both the codepoint and grapheme end limits are reached.

After initialization

  • Limited storages can be completed on demand.
  • If the error storage is enabled, it is updated each time an invalid byte sequence is encountered.
  • The errors "Code point index is not stored" and "Grapheme index is not stored" are not raised.
  • When a requested index is not yet stored, that index is stored, along with any missing intermediate indexes. The requested index is therefore always made available by extending the appropriate storage, rather than raising an error because the index was not previously stored.
  • The storage to be updated (start or end) is selected based on which requires storing fewer intermediate indexes. When the distance is the same, the start storage is used because forward decoding is faster than backward decoding.

Note

To decode a grapheme, codepoints must be decoded until a grapheme break is detected.

  • When decoding forward, if the end of the string has not been reached, a codepoint beyond the grapheme's last codepoint will be decoded and stored, along with any related error.
  • When decoding backward, if the start of the string has not been reached, the codepoint immediately preceding the grapheme's first codepoint will be decoded and stored, along with any related error.

This extra codepoint (and possibly extra error) is expected and safely handled without duplication.

Invariants

  • At the end of initialization:

    • A full forward scan has been performed, independently of the specified limits:

      • i0sg startGraphemeIndexes~items = min(startGraphemeStorageLimit, graphemeCount) where startGraphemeStorageLimit is the value returned by ~limits.
      • i0sc startCodepointIndexes~items = min(startCodepointStorageLimit, codepointCount) where startCodepointStorageLimit is the value returned by ~limits.

    • A limited backward scan has been performed, depending on the adjusted limits:

      • i0eg endGraphemeIndexes~items = min(endGraphemeStorageLimit, graphemeCount) where endGraphemeStorageLimit is the value returned by ~limits.
      • i0ec endCodepointIndexes~items = min(endCodepointStorageLimit, codepointCount) where endCodepointStorageLimit is the value returned by ~limits.

    • i1 When the start codepoint storage does not hold all codepoints (startCodepointStorageCount < codepointCount), it ends on a grapheme boundary:

      • the last index LI in the start codepoint storage is the byte index of the extra look-ahead codepoint, which is the first codepoint of a grapheme G.
      • When the start grapheme storage is enabled, G is the grapheme that follows the last stored one.

    • i2 When the start and end codepoint storages together do not hold all codepoints (startCodepointStorageCount + endCodepointStorageCount < codepointCount), and the end grapheme storage is enabled, the end codepoint storage ends on a grapheme boundary:

      • If greater than 1, the last index LI in the end codepoint storage is the byte index of the last codepoint LC1 of a grapheme G1.
      • The codepoint FC2 that follows on the right the codepoint LC1 starts a grapheme G2.
      • When the end grapheme storage is enabled, its last (leftmost) index is the index of FC2.
      • The only exception is when that leftmost grapheme is invalid: the backward step has no look-behind, so LI is the index of FC2.

  • At any time:

    • i3 (see exception below)
      If the start error storage is enabled:
      startErrorMessages~items == max(count of negative indexes in indexer~startGraphemeIndexes, count of negative indexes in indexer~startCodepointIndexes).

    • i4 (see exception below)
      If the end error storage is enabled:
      endErrorMessages~items == max(count of negative indexes in indexer~endGraphemeIndexes, count of negative indexes in indexer~endCodepointIndexes).

    • Exception to i3 and i4: when the start and end error storages together hold all errors (startErrorStorageCount + endErrorStorageCount == errorCount), a stored index can be negative without its message in that storage. The other storage already holds the message, and no overlap is allowed.

-- The limits are adjustable.
-- If the end grapheme storage is not enabled:
--   a reverse codepoint supplier is used for the backward scan during the initialization.
--   the codepoint storage can end in the middle of a grapheme.

aRexxUnicodeStringIndexer~endErrorMessages

Returns an array containing a copy of the error messages stored in the end storage.

    /*
    an Array (shape [1], 1 items)

7.3.14.   graphemeIndexB

aRexxUnicodeStringIndexer~graphemeIndexB( indexG, next = .false, raiseError = .true )

Returns the byte index corresponding to grapheme index indexG.
It is negative if the grapheme's byte sequence is invalid.

indexG must be a positive or negative whole number.
If indexG is negative, the grapheme index is counted from the end of the string.

next is a boolean, with a default value of .false.
If next is .true, the byte index corresponding to the next grapheme index is returned. This is different from requesting the byte index of indexG + 1, because indexG + 1 may be considered too large.

If raiseError is .true (the default), an error is raised when:

  • indexG is zero.
  • abs(indexG) exceeds the grapheme count.
  • the requested index is not stored and the indexer is non-incremental.

If raiseError is .false, .nil is returned in case of error.

For an explanation of storage, see RexxUnicodeStringIndexer~new and RexxUnicodeStringIndexer~newIncremental.

9.   ICU4ooRexxInterface Class

The ICU4ooRexxInterface class provides the interface used by the ICU4ooRexx library to register its services with RexxUnicode.

ICU4ooRexxInterface is a private mixin class inherited by RexxUnicode.
Its public methods are exposed through RexxUnicode.

9.1.4.   registerICU4ooRexx

.ICU4ooRexxInterface~registerICU4ooRexx( package )

Registers the specified ICU4ooRexx package.

Possible error messages:

  • ICU4ooRexx is already registered with a different package.
  • Class ICU4ooRexx not found.
  • The minimum required ICU4ooRexx version is versionRequirement; the current version is version.
  • The ICU4ooRexx class does not understand the message u_charName.
  • The ICU4ooRexx class does not understand the message u_charFromName.

Examples

-- Example 1
-- Copied from the prolog of ICU4ooRexx.cls

-- If rxunicode.cls has been loaded by the user, register ICU4ooRexx.
-- This will make ICU4ooRexx available to the rxunicode package.
if .RexxUnicode~isa(.Class), .RexxUnicode~hasMethod("registerICU4ooRexx") then do
    .RexxUnicode~registerICU4ooRexx(.context~package)
end

-- Example 2
-- The ICU4ooRexx package is registered by the user.

-- If rxunicode.cls is not loaded before ICU4ooRexx.cls, the automatic registration is not done.
.context~package~loadPackage("ICU4ooRexx.cls")
.context~package~loadPackage("rxunicode.cls")
say .RexxUnicode~ICU4ooRexxIsRegistered                             -- 0
ICU4ooRexxClass = .context~package~findPublicClass("ICU4ooRexx")
.RexxUnicode~registerICU4ooRexx(ICU4ooRexxClass~package)
say .RexxUnicode~ICU4ooRexxIsRegistered                             -- 1

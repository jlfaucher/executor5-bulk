
Necessary steps to perform when making a new release for ooRexx

The following examples assumes working from a remote computer using ssh/scp,
amend as necessary.

1. All the footwork done for a release (Ricks document release-steps.md, copyright update etc)
   and a Release Candidate in main/branches/5.2/trunk (check this before using the script)

2. Make a complete backup of Jenkins using jenkinsTotalBup.sh, date it and if possible store
   away to DATA disk.

   ssh -p 2208 jenkins@build.oorexx.org
   bash jenkinsTotalBup.sh
   mv jenkinsTotalBup.zip  /media/DATA/BUP/2026-04-18_jenkinsTotalBup.zip

3. Zip and copy the jobs from Jenkins back to the local repository with full path

   zip -r var.zip /var/lib/jenkins/jobs/* 
   scp -P 2216 var.zip jenkins@build.oorexx.org:/Users/jenkins/Downloads/Release
   rm var.zip
   exit

IMPORTANT

4. On the machine where the documentation is built make a complete copy of the
   Documentation job folder ooRexx-docs-build -> ooRexx-docs-build-COPY
   In this way it can be restored if something goes wrong

   and thereafter clean out all old build files in ooRexx-docs-build
   zip, html, fo, pdf and delete version files both old and new
   also SVN should be emptied

5. Extract var.zip WITH COMPLETE PATH /var/lib/jenkins/jobs/* to a work folder
   Copy Modifybuildjobs.rex to the same folder

   unzip var.zip
   cp -r var ReleaseTest/var

NOTE: Work folder can be on Jenkins Controller itself or on another machine
Examples here assume working from a remote machine

6. Log in to Sourceforge and create one NON-STAGED folder for the new documentation build 
   /projects/oorexx/files/oorexx-docs/5.2.0_Release_Candidate

7. Create 2 NON-STAGED folders on Sourceforge
   /projects/oorexx/files/oorexx/ 5.2.0_Release_Candidate
   /projects/oorexx/files/oorexx/ 5.2.0_Release_Candidate/portable

8. In the script Modifybuildjobs.rex modify these items (example for 5.2.0)
   Check revision using SVN update on local SVN copy /Users/jenkins/ooRexxSVN-Code-0
   cd  /Users/jenkins/ooRexxSVN-Code-0
   % svn update -> Revision 13156.

   Modify Modifybuildjobs.rex to include the correct new paths
   needle = current path
   newneedle = the release path

-- needle1 for all build jobs, also for source package build
   needle1     ='<remote>https://svn.code.sf.net/p/oorexx/code-0/main/trunk</remote>'
   newneedle1  ='<remote>https://svn.code.sf.net/p/oorexx/code-0/main/branches/5.2.0/trunk</remote>'

-- needle 2 and needle3 are for the documentation build
-- remember we must build the complete release documentation once before we build the installers
   needle2     ='<remote>https://svn.code.sf.net/p/oorexx/code-0/docs/trunk</remote>'
   newneedle2  ='<remote>https://svn.code.sf.net/p/oorexx/code-0/docs/branches/5.2.0/trunk</remote>'

   needle3     ='rexx BuildandUploadDocs.rex svn.code.sf.net/p/oorexx/code-0/docs/trunk /home/frs/project/oorexx/oorexx-docs/5.2.0beta'
   newneedle3  ='rexx BuildandUploadDocs.rex svn.code.sf.net/p/oorexx/code-0/docs/branches/5.2.0/trunk /home/frs/project/oorexx/oorexx-docs/5.2.0'

-- ooRexx-sourceforge-upload and ooRexx-sourceforge-zip-installer-upload can take 3 arguments:
-- the upload folder tail part
-- the version number indicated in the filename
-- the min revision, set to release number minus one
   needle4     ='rexx jenkinsArtifactUpload.rex 5.2.0beta 5.2.0 0'
   newneedle4  ='rexx jenkinsArtifactUpload.rex 5.2.0 5.2.0 13155'

-- https://sourceforge.net/projects/oorexx/files/oorexx/5.2.0/portable/
   needle5     ='rexx jenkinsZIPArtifactUpload.rex 5.2.0beta 5.2.0 0'
   newneedle5  ='rexx jenkinsZIPArtifactUpload.rex 5.2.0 5.2.0 13155'

-- ooRexx tests jobs new 2026-04-18
   needle6     ='<remote>https://svn.code.sf.net/p/oorexx/code-0/test/trunk</remote>'
   newneedle6  ='<remote>https://svn.code.sf.net/p/oorexx/code-0/test/branches/5.2.0/trunk</remote>'

9. Run Modifybuildjobs.rex
   This will find and replace all needles with newneedles in all jobs

NOTE: In order to be successful most builds need a fresh copy of the documentation. Due to the "Blocking Job" this is now automatic

10. Stop Jenkins from running on Jenkins master
   From remote use ssh to connect to jenkins controller

   ssh -p 2208 jenkins@build.oorexx.org
   sudo service jenkins stop
   exit
   This is absolutely essential to do before anything else.

11. Copy back the modified folders from .../jobs to /var/lib/jenkins/jobs
   This is done from remote workdir (in my case from .../Release)

   scp -rpP 2208 var/lib/jenkins/jobs/* jenkins@build.oorexx.org:/var/lib/jenkins/jobs

12. Start jenkins again
   ssh -p 2208 jenkins@build.oorexx.org
   sudo service jenkins start
   If all goes well the build of the documentation should start and
   upload to Sourceforge folder under oorexx-docs

13. The release of the remaining jobs should now follow automatically
   Monitor that all platforms are built.

14. The upload scripts have a delay, let them run and monitor the Upload folders
   on Sourceforge

15. Check the Sourceforge folder, it might be that some older items got uploaded
   This is normally prevented by the switches to the uploading script but
   there might be a few older builds that need to be deleted manually

MOVING TO THE NEXT BETA AFTER RELEASE 5.2.0 -> 5.3.0Beta
 
1. as soon as all artifacts have been uploaded stop Jenkins from running on Jenkins master
   From remote use ssh to connect to jenkins controller

   ssh -p 2208 jenkins@build.oorexx.org
   sudo systemctl stop jenkins
   exit

2. Log in to Sourceforge and create one NON-STAGED folder for the next Beta documentation build 
   /projects/oorexx/files/oorexx-docs/5.3.0beta

3. Create 2 NON-STAGED folders on Sourceforge for the next Beta
   /projects/oorexx/files/oorexx/5.3.0beta
   /projects/oorexx/files/oorexx/5.3.0beta/portable

4. Rename the previous var folder to var-520, unzip a fresh copy or var

5. In the script Modifybuildjobs.rex modify these items (example for 5.2.0beta -> 5.3.0Beta)

   Modify Modifybuildjobs.rex to include the correct new paths.
   needle = current path
   newneedle = the release path

-- needle1 for all build jobs, also for source package build
   needle1     ='<remote>https://svn.code.sf.net/p/oorexx/code-0/main/trunk</remote>'
   newneedle1  ='<remote>https://svn.code.sf.net/p/oorexx/code-0/main/trunk</remote>'

-- needle 2 and needle3 are for the documentation build
-- remember we must build the complete release documentation once before we build the installers
   needle2     ='<remote>https://svn.code.sf.net/p/oorexx/code-0/docs/trunk</remote>'
   newneedle2  ='<remote>https://svn.code.sf.net/p/oorexx/code-0/docs/trunk</remote>'

   needle3     ='rexx BuildandUploadDocs.rex svn.code.sf.net/p/oorexx/code-0/docs/trunk /home/frs/project/oorexx/oorexx-docs/5.2.0beta'
   newneedle3  ='rexx BuildandUploadDocs.rex svn.code.sf.net/p/oorexx/code-0/docs/trunk /home/frs/project/oorexx/oorexx-docs/5.3.0beta'

-- ooRexx-sourceforge-upload and ooRexx-sourceforge-zip-installer-upload can take 3 arguments:
-- the upload folder tail part
-- the version number indicated in the filename
-- the min revision, set to release number minus one (or 0 for all)
   needle4     ='rexx jenkinsArtifactUpload.rex 5.2.0beta 5.2.0 0'
   newneedle4  ='rexx jenkinsArtifactUpload.rex 5.3.0beta 5.3.0 0'

-- https://sourceforge.net/projects/oorexx/files/oorexx/5.3.0beta/portable/
   needle5     ='rexx jenkinsZIPArtifactUpload.rex 5.2.0beta 5.2.0 0'
   newneedle5  ='rexx jenkinsZIPArtifactUpload.rex 5.3.0beta 5.3.0 0'

-- ooRexx tests jobs
   needle6     ='<remote>https://svn.code.sf.net/p/oorexx/code-0/test/trunk</remote>'
   newneedle6  ='<remote>https://svn.code.sf.net/p/oorexx/code-0/test/trunk</remote>'

6. Run Modifybuildjobs.rex
   This will find and modify all needles with newneedles in all jobs

7. Copy back the modified folders from .../jobs to /var/lib/jenkins/jobs
   This is done from remote workdir (in my case from .../Release)

   scp -rpP 2208 var/lib/jenkins/jobs/* jenkins@build.oorexx.org:/var/lib/jenkins/jobs

8. Perform the necessary steps in release-steps.md

9. Start jenkins again
   ssh -p 2208 jenkins@build.oorexx.org
   sudo service jenkins start
   If all goes well the build of the documentation should start and
   upload to Sourceforge folder under oorexx-docs

10. Check that everything looks ok and that all platforms are connected
